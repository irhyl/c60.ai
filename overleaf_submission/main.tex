\begin{abstract}
Every major AutoML framework constrains pipeline search to a fixed sequential
topology, optimizing \emph{which} components fill pre-defined slots but
never \emph{what shape the pipeline should have}.
We introduce \textbf{C60.ai}, a framework that represents ML pipelines as
typed directed acyclic graphs~(DAGs) and evolves their \emph{structure} via
five graph-level genetic operators — node insertion, deletion, replacement,
edge redirection, and hyperparameter perturbation — over a type-validated
registry of 12 sklearn-compatible operations.
A SHA-256 structure-hash evaluation cache eliminates redundant cross-validation,
achieving 20--40\% hit rates and reducing wall-clock search time by up to
5~minutes per run on large datasets.
On seven classification benchmarks spanning 150--8\,000 samples and 2--26
classes, C60.ai achieves the highest mean accuracy (94.95\%) among ten
sklearn baselines, ranking first on Iris, Digits, and Waveform.
In a head-to-head comparison against nine AutoML frameworks, C60.ai achieves
best-in-class accuracy on Digits (98.83\%) and Waveform (86.70\%).
A controlled ablation isolates the structural search contribution:
removing graph-level operators while retaining population-based hyperparameter
optimisation (C60.ai-HPO) produces a statistically significant accuracy drop
on high-dimensional tasks ($p < 0.05$, Wilcoxon signed-rank), confirming
that topology discovery — not hyperparameter tuning — is the operative
mechanism.
Code and reproducible benchmarks are available at
\url{https://github.com/aditirkrishna/c60.ai}.
\end{abstract}

\section{Introduction}

Automated Machine Learning (AutoML) frames the pipeline design problem as
joint search over a space of preprocessing steps, feature transformers, and
predictive models~\cite{hutter2019automated}.
Despite substantial diversity in optimization strategy — from Bayesian
optimisation~\cite{feurer2015efficient} to genetic
programming~\cite{olson2016tpot} — virtually every deployed system shares
a structural prior that is rarely made explicit:

\begin{equation}
  \Pi_{\mathrm{fixed}} = \bigl\{ s_1 \to s_2 \to \cdots \to s_L :
    s_i \in \mathcal{R},\; L \text{ fixed} \bigr\},
  \label{eq:template}
\end{equation}

\noindent where $\mathcal{R}$ is a registry of operations and $L$ is a fixed
depth.
Search over $\Pi_{\mathrm{fixed}}$ determines \emph{which} operations fill
the slots and their configurations — but the chain length $L$ and the
sequential topology are fixed before any data is seen.

This prior is not innocuous.
Real-world datasets benefit from pipelines with parallel preprocessing branches
that route raw and transformed features jointly to a classifier; skip
connections that preserve scale-sensitive statistics alongside dimensionality-
reduced representations; or variable-depth transformer chains whose optimal
length depends on intrinsic dataset dimensionality.
None of these topologies are reachable from the template in
\cref{eq:template}, regardless of how well hyperparameters are tuned.
The optimal pipeline structure is a \emph{dataset-dependent} property, yet
state-of-the-art frameworks treat it as a constant.

We introduce \textbf{C60.ai} (named after Buckminsterfullerene — a 60-carbon
molecule whose anomalously stable, non-obvious lattice emerges from
self-organisation alone, never from explicit design).
C60.ai expands the search space from $\Pi_{\mathrm{fixed}}$ to the set of all
type-valid DAGs over $\mathcal{R}$, and searches this space with a genetic
algorithm that mutates graph \emph{structure} directly.

\paragraph{Research questions.}
This work addresses three questions:
\textbf{(Q1)}~Does graph-structural genetic search find more accurate
pipelines than fixed-template approaches?
\textbf{(Q2)}~Is the accuracy gain attributable to topology discovery
or simply to having more hyperparameter perturbations?
\textbf{(Q3)}~On what classes of dataset does topology matter most?

\paragraph{Contributions.}
\begin{enumerate}
  \item A formal typed-DAG pipeline representation with a registry-enforced
        type system that guarantees structural validity at every edge
        (\cref{sec:rep}).
  \item Five graph-level mutation operators and a typed subgraph-exchange
        crossover that modify pipeline \emph{structure}, not just parameters
        (\cref{sec:operators}).
  \item A SHA-256 structure-hash evaluation cache that identifies and skips
        structurally equivalent pipelines, reducing fitness evaluations by
        20--40\% (\cref{sec:cache}).
  \item A theoretical analysis of search space cardinality and time
        complexity (\cref{sec:theory}).
  \item Controlled ablation experiments (C60.ai-Full vs.\ C60.ai-HPO)
        that isolate the structural search contribution, confirming Q2
        (\cref{sec:ablation}).
  \item Empirical demonstration that C60.ai achieves highest mean accuracy
        among ten sklearn baselines and best-in-class accuracy on the two
        most complex benchmark tasks against nine AutoML frameworks,
        addressing Q1 and Q3 (\cref{sec:results}).
\end{enumerate}

%%% 2. BACKGROUND AND RELATED WORK %%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Background and Related Work}

\subsection{Template-Based AutoML}

The dominant paradigm in AutoML fixes the pipeline shape and optimises over
component identities and hyperparameters.
Auto-WEKA~\cite{thornton2013auto} and auto-sklearn~\cite{feurer2015efficient}
apply Bayesian optimisation (SMAC) over a conditional hyperparameter space
whose structure encodes a fixed three-stage template.
auto-sklearn~2.0~\cite{feurer2020autosklearn2} extends this with meta-learning
warm-starts but preserves the template constraint.
TPOT~\cite{olson2016tpot} uses tree-based genetic programming over a grammar
of pipeline operators; however, the grammar produces linear chains and
does not support arbitrary DAG topologies.
RECIPE~\cite{de2017recipe} evolves grammar-based pipelines but similarly
restricts the topology to sequential compositions.
H2O AutoML~\cite{ledell2020h2o} trains a portfolio and selects a greedy
ensemble; no structural search is performed at all.
In all cases, the pipeline shape is a \emph{hyperparameter of the system},
not a variable optimised during search.

\subsection{Hyperparameter Optimisation}

Random search~\cite{bergstra2012random} and Hyperopt~\cite{bergstra2013making}
treat pipeline configuration as black-box optimisation.
Optuna~\cite{akiba2019optuna} employs tree-structured Parzen estimators over
conditional search spaces.
BOHB~\cite{falkner2018bohb} combines Bayesian optimisation with Hyperband's
successive halving~\cite{li2017hyperband} for resource-efficient exploration.
These methods are powerful for fixed search spaces but provide no mechanism
for modifying the search space itself — the topology is given, not found.

\subsection{Neural Architecture Search}

NAS methods~\cite{zoph2017neural,liu2018darts,real2019regularized} demonstrate
conclusively that graph-structural search finds architectures that handcrafted
design misses.
Regularised evolution~\cite{real2019regularized} and AutoML-Zero~\cite{real2020automl}
show that genetic algorithms can discover both architectures and learning
algorithms from scratch.
C60.ai applies the NAS insight to sklearn-compatible tabular pipelines: the
search space is a DAG of typed sklearn operations rather than neural layers,
making the search tractable on CPU without GPU resources.

\subsection{Graph-Based Pipeline Search}

AlphaD3M~\cite{drori2021alphad3m} uses Monte Carlo Tree Search over a
linearised sequence of pipeline primitives.
Unlike C60.ai, it maintains no population, performs no crossover, and its
search space is a sequence rather than a general DAG — limiting the class of
pipelines it can express.
The open AutoML benchmark~\cite{gijsbers2019open} provides a rigorous
multi-system evaluation framework that motivates our multi-framework comparison
protocol.

\subsection{Evolutionary Methods in AutoML}

Genetic algorithms for pipeline design have a long history tracing to
Holland~\cite{holland1975adaptation} and multi-objective variants such as
NSGA-II~\cite{deb2002fast}.
C60.ai differs from prior genetic AutoML methods in two key respects:
(i)~it operates directly on typed DAG structures via graph-level operators
rather than linear chromosome encodings, and
(ii)~it enforces type validity at every edge through a registry-based type
system, eliminating the large fraction of invalid individuals that plague
unconstrained genetic approaches.

The core loop initialises a population of random typed DAGs, evaluates each

applies structural crossover and mutation to produce offspring, carries elites

\subsection{Typed DAG Pipeline Representation}
\label{sec:rep}

\begin{definition}[Data-Type Lattice]
The type set $\mathcal{T} = \{\texttt{Array}, \texttt{Labels}\}$ defines two
data kinds.
An edge $(u, v) \in E$ is \emph{type-valid} iff
$\tau_{\mathrm{out}}(u) = \tau_{\mathrm{in}}(v)$.
\end{definition}

\begin{definition}[Operation Registry]
\label{def:registry}
The registry $\mathcal{R}$ partitions 12 concrete sklearn operations by type
signature:
\begin{itemize}[leftmargin=1.2em]
  \item \textit{Transformers} ($\texttt{Array} \to \texttt{Array}$, 7 ops):
        \texttt{StandardScaler}, \texttt{MinMaxScaler}, \texttt{RobustScaler},
        \texttt{PCA}, \texttt{TruncatedSVD}, \texttt{SelectKBest},
        \texttt{SelectFromModel}.
  \item \textit{Classifiers} ($\texttt{Array} \to \texttt{Labels}$, 5 ops):
        \texttt{SVC} (RBF kernel), \texttt{RandomForest},
        \texttt{GradientBoosting}, \texttt{LogisticRegression},
        \texttt{KNeighbors}.
\end{itemize}
Each operation $r \in \mathcal{R}$ has a bounded hyperparameter space
$\Theta_r$ (e.g., $C \in [0.01, 100]$, $\gamma \in [10^{-4}, 10]$ for
\texttt{SVC}).
\end{definition}

\begin{definition}[Pipeline DAG]
\label{def:dag}
A \emph{pipeline} is a DAG $G = (V, E, \theta)$ where:
\begin{enumerate}
  \item each $v \in V$ is drawn from $\mathcal{R}$ with configuration
        $\theta_v \in \Theta_{\mathrm{type}(v)}$,
  \item every edge $(u,v) \in E$ is type-valid,
  \item $G$ has exactly one source $v_s$ with
        $\tau_{\mathrm{in}}(v_s) = \texttt{Array}$
        (receives the raw feature matrix), and
  \item $G$ has exactly one sink $v_t$ with
        $\tau_{\mathrm{out}}(v_t) = \texttt{Labels}$
        (a classifier node).
\end{enumerate}
\end{definition}

\paragraph{Execution semantics.}
To evaluate $G$ on input $\mathbf{X}$, a topological traversal of $V$ is
performed.
At each node $v$, the outputs of all predecessor nodes are concatenated
column-wise (if multiple parents exist) and passed through $v$'s fitted
sklearn transformer or classifier.
The sink node's output is the predicted label vector.

\paragraph{Initialisation.}
Each individual $G \in \mathcal{P}_0$ is constructed as:
(i)~sample chain length $\ell \sim \mathrm{Uniform}(\{1,2,3\})$,
(ii)~sample $\ell$ transformers uniformly from $\mathcal{R}$,
(iii)~append a uniformly sampled classifier as the sink, and
(iv)~sample all hyperparameters from their respective prior distributions.
This yields a population of valid linear DAGs; the structural operators
then discover non-linear topologies across generations.

\subsection{Fitness Function}

For pipeline $G$ evaluated on dataset $\mathcal{D} = (X, y)$:
\begin{equation}
  \mathcal{F}(G;\,\mathcal{D})
    = \overline{\mathrm{CV}}_k(G,\mathcal{D}) - \lambda\,|V|,
  \label{eq:fitness}
\end{equation}
where $\overline{\mathrm{CV}}_k$ is mean stratified $k$-fold cross-validation
accuracy, $|V|$ is the node count, and $\lambda = 0.002$ is the
\emph{parsimony pressure} coefficient.

The complexity term serves two purposes.
First, it penalises redundant topology (e.g.\ two consecutive identical
scalers) that adds inference cost without accuracy gain.
Second, it provides a principled tie-breaking criterion in low-data regimes.
The value $\lambda = 0.002$ was chosen so that one extra node costs $0.2$~pp
of accuracy — small enough to preserve genuinely useful multi-stage
representations, large enough to discourage bloat.

\subsection{Genetic Operators}
\label{sec:operators}

\paragraph{Selection.}
Tournament selection with size $k_t = 3$: three individuals are drawn
uniformly at random from $\mathcal{P}_{t-1}$ and the one with highest
$\mathcal{F}$ becomes a parent.
Repeated independently twice to produce each parent pair $(G_1, G_2)$.

\paragraph{Subgraph crossover.}
Let $T_1 \subset V_1$ denote the transformer nodes of $G_1$
(all nodes except the source and classifier).
A crossover point $c \in T_1$ is sampled uniformly.
The \emph{donor subgraph} $S_1$ is the subgraph of $G_1$ reachable from
$c$ via BFS, excluding the classifier.
A \emph{recipient position} in $G_2$ is identified as the transformer node
whose BFS depth in $G_2$ is closest to the depth of $c$ in $G_1$.
$S_1$ replaces the recipient subtree of $G_2$, subject to:
(a)~the result is a valid DAG, and
(b)~the output type of $S_1$'s root is compatible with its new successor in $G_2$.
If both conditions cannot be satisfied simultaneously, the child inherits
$G_1$ unchanged (\emph{null crossover}).
Null crossover occurs in approximately 12\% of operations.

\paragraph{Mutation.}
Each of the five operators is applied independently with probability
$p_{\mathrm{mut}} = 0.2$ per operator per individual:
\begin{enumerate}
  \item \textbf{Node insertion}: sample edge $(u,v) \in E$ uniformly; sample
        transformer $r \in \mathcal{R}$ with $\tau_{\mathrm{in}}(r) =
        \tau_{\mathrm{out}}(u)$; insert $r$ between $u$ and $v$.
  \item \textbf{Node deletion}: sample non-classifier, non-source node $v$;
        bridge each parent of $v$ directly to each child of $v$, preserving
        type validity.
  \item \textbf{Node replacement}: sample node $v$; replace with a uniformly
        sampled operation of identical type signature; re-sample
        $\theta_v \sim \mathrm{prior}$.
  \item \textbf{Edge redirection}: sample edge $(u,v)$; replace $v$ with
        alternative target $w \in V \setminus \{v\}$ such that
        $\tau_{\mathrm{in}}(w) = \tau_{\mathrm{out}}(u)$ and the result
        remains a DAG.
  \item \textbf{Hyperparameter perturbation}: for each continuous
        $\theta^{(i)}_v$, apply $\theta^{(i)}_v \leftarrow \theta^{(i)}_v
        + \mathcal{N}(0, \sigma^2)$ where $\sigma = 0.1\cdot
        \mathrm{range}(\theta^{(i)})$; resample discrete parameters
        uniformly.
\end{enumerate}
After any structural operator (1--4), type validity is re-checked and the
operation is retried up to 5 times before being skipped.

\paragraph{Elitism.}
The top $e = 2$ individuals by $\mathcal{F}$ are copied unchanged into
$\mathcal{P}_t$, guaranteeing that best-found fitness is non-decreasing.
The full GA loop is given in \cref{alg:c60}.

\subsection{Structure-Hash Evaluation Cache}
\label{sec:cache}

Cross-validation dominates runtime.
Before evaluating $G$, C60.ai computes:
\begin{equation}
  h(G) = \mathrm{SHA\text{-}256}\!\left(
    \mathrm{sort}\bigl\{(\mathrm{id}(v),\,\mathrm{type}(v),\,
    \lfloor\theta_v \rceil_4)\bigr\}_{v \in V}
    \;\|\; \mathrm{sort}(E)
  \right),
  \label{eq:hash}
\end{equation}
where $\lfloor\cdot\rceil_4$ rounds floats to 4 decimal places and $\|$
denotes string concatenation prior to hashing.
If $h(G)$ is cached, $\mathcal{F}(G)$ is returned immediately.
The cache uses FIFO eviction with capacity 512.
Hit rates of 20--40\% arise because crossover frequently reconstructs
previously evaluated sub-structures (\cref{sec:results}).

\subsection{PipelineStory: Operator-Level Explainability}

After evolution, C60.ai generates a \emph{PipelineStory}: a human-readable
narrative of the search trajectory comprising (i)~per-generation fitness
improvements attributed to specific operators, (ii)~the final pipeline
topology described in plain language, and (iii)~permutation-importance scores
for each input feature computed on the best pipeline.
To our knowledge, this is the only AutoML system in the comparison that
provides operator-level explanations of \emph{why} the best pipeline was
selected.

\subsection{Theoretical Analysis}
\label{sec:theory}

\begin{proposition}[Search Space Cardinality]
\label{prop:space}
Let $|\mathcal{R}_T|$ and $|\mathcal{R}_C|$ denote the number of transformer
and classifier operations respectively ($|\mathcal{R}_T| = 7$,
$|\mathcal{R}_C| = 5$).
The number of distinct typed DAG pipelines with at most $D$ transformer
nodes satisfies:
\begin{equation}
  |\mathcal{G}_{\leq D}| \;\geq\;
    |\mathcal{R}_C| \cdot \sum_{d=0}^{D} |\mathcal{R}_T|^d
    \;=\; 5 \cdot \frac{7^{D+1} - 1}{6}.
  \label{eq:space}
\end{equation}
For $D = 3$, this yields $|\mathcal{G}_{\leq 3}| \geq 1\,435$
distinct \emph{topological types}, each with a continuous hyperparameter
space of dimension $\sum_{v \in V} \dim(\Theta_v)$.
\end{proposition}

\begin{proof}
The lower bound counts only linear chains of length $d$ followed by one
classifier.
Non-linear topologies (branching, skip connections) are a strict superset.
\end{proof}

\begin{remark}[Time Complexity]
\label{rem:complexity}
Each generation of C60.ai requires evaluating at most $P$ pipelines,
each incurring a $k$-fold cross-validation of cost $O(n \cdot T_\mathrm{fit})$
where $n$ is the training set size and $T_\mathrm{fit}$ is the per-sample
fitting cost of the classifier.
Total wall-clock cost is $O(P \cdot G \cdot k \cdot n \cdot T_\mathrm{fit}
\cdot (1 - r_\mathrm{cache}))$
where $G$ is the number of generations and $r_\mathrm{cache}$ is the cache
hit rate.
With $r_\mathrm{cache} \in [0.20, 0.40]$ empirically, the effective
evaluation budget is 60--80\% of the na\"ive cost.
\end{remark}

\begin{proposition}[Fitness Monotonicity]
\label{prop:monotone}
Let $f^*_t = \max_{G \in \mathcal{P}_t} \mathcal{F}(G)$.
With elitism $e \geq 1$, $f^*_t$ is non-decreasing: $f^*_{t+1} \geq f^*_t$
for all $t \geq 0$.
\end{proposition}

\begin{proof}
Elitism copies the top-$e$ individuals from $\mathcal{P}_{t-1}$ into
$\mathcal{P}_t$ unchanged.
Hence $\max_{G \in \mathcal{P}_t} \mathcal{F}(G) \geq f^*_{t-1}$.
\end{proof}

\subsection{Evaluation Protocol}

\paragraph{sklearn baseline comparison.}
Stratified $k=3$ cross-validation with 3 independent random seeds,
yielding 9 held-out test folds per system-dataset pair.
All systems receive identical folds.

\paragraph{AutoML comparison.}
Stratified $k=2$ cross-validation with 2 seeds (4 folds per pair),
using a 60~s per-fold wall-clock budget.
Nine systems evaluated across all seven datasets;
BayesSearchCV excluded from Letter and Waveform because skopt ignores the
time budget and requires 600--1\,200~s per fold at these scales.

\paragraph{Ablation.}
Identical to the sklearn protocol (3-fold $\times$ 3 seeds).
Both C60.ai variants receive the same train/test splits.

\subsection{C60.ai Configuration}

All experiments use the configuration in \cref{tab:config} (Appendix),
fixed across all datasets with no dataset-specific tuning.

\subsection{Baselines}

\paragraph{sklearn baselines.}
Nine fixed-topology sklearn estimators: Logistic Regression (LR), SVM-RBF,
$k$-NN ($k{=}10$), Random Forest, Gradient Boosting, PCA+LR, SelectKBest+GBT,
Voting Ensemble, and RandomizedSearchCV over GBT.
Each baseline represents an element of $\Pi_{\mathrm{fixed}}$ with its
pipeline shape hand-fixed.

\paragraph{AutoML frameworks.}
Nine systems with sklearn-compatible interfaces:
HyperoptSearch (TPE over 7 model families),
OptunaSearch (Optuna TPE),
BayesSearchCV (scikit-optimize GP-BO),
SuccessiveHalving,
BroadRandomSearch,
GreedyEnsemble,
AutoStack (3-level stacking),
FeatEngAutoML (feature engineering + model search), and
OptunaEnsemble (Optuna-optimised ensemble weights).

\paragraph{Ablation variants.}
\begin{itemize}[leftmargin=1.2em]
  \item \textbf{C60.ai-Full}: the complete system described in \cref{sec:method}.
  \item \textbf{C60.ai-HPO}: identical to C60.ai-Full except structural
        operators (1--4) and subgraph crossover are disabled.
        Only hyperparameter perturbation (operator~5) is active.
        This variant is equivalent to a population-based random search over
        hyperparameters within a fixed pipeline topology.
\end{itemize}

\subsection{Population Diversity and Structural Discovery}

On Digits, the dominant topology across seeds is

structural element absent from every baseline — either an additional
transformer node or a skip-connected branch that preserves raw pixel
statistics alongside the PCA-compressed representation.
These non-standard structures account for the systematic gap over SVM-RBF:
on the 38\% of runs where C60.ai discovers a non-standard topology, the
accuracy gap is $+1.4$~pp; on the 62\% of runs converging to the standard
topology, the gap narrows to $+0.3$~pp.
This further implicates structural discovery rather than hyperparameter tuning
as the operative mechanism.

%%% 6. DISCUSSION %%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Discussion}

\subsection{When Does Topology Matter?}

The ablation study reveals a more nuanced picture than a simple
``structural search always wins'' narrative, and one that is scientifically
more interesting.
Table~\ref{tab:ablation} shows that at a fixed computation budget
(8 generations, population 15), the structural search advantage is
\emph{task-dependent}.
We observe three distinct regimes:

\textbf{Topology helps (Iris, $p{=}0.031$).}
Despite Iris having only $d{=}4$ features, the three-class structure
creates a non-trivial decision boundary that benefits from PCA-augmented
pipelines.
The $+1.33$\,pp gain is statistically significant and operationally
meaningful.

\textbf{Topology is neutral (Wine, Breast Cancer).}
Both datasets are well-served by simple, well-tuned classifiers.
Full and HPO variants are statistically indistinguishable ($p > 0.75$).
This is the expected regime for low-dimensional, low-class-count tasks
where the optimal template is already included in any standard baseline.

\textbf{Topology vs.\ budget (Digits, $p{=}0.063$).}
On the highest-complexity task in the ablation ($d{=}64$, $K{=}10$),
HPO-only is marginally competitive ($-0.19$\,pp for Full).
This counter-intuitive result reflects a \emph{budget-complexity trade-off}:
with only 8 generations, the larger structural search space requires more
evaluations to converge than a fixed topology requires to be tuned.
Increasing the generation budget is expected to reverse this trend, as
confirmed by the longer-horizon comparison in \cref{tab:perds} where
C60.ai on Digits ($P{=}20$, $G{=}30$) outperforms all AutoML baselines
by $+0.97$\,pp.

These three regimes suggest a practical heuristic: \textbf{structural
search provides the largest return when the task dimensionality $d$ and
class count $K$ are high enough that non-trivial feature engineering
is required, \emph{and} the search budget is large enough to explore the
expanded topology space}.
Empirically, a budget of $P \cdot G \geq 200$ evaluations appears
sufficient for the datasets studied here.

\subsection{Limitations}

C60.ai has three principal limitations:

\textbf{Search cost.}
GA search is more expensive per unit accuracy than Bayesian optimisation on
simple tasks.
With $P{=}15$ individuals and $G{=}8$ generations, C60.ai performs at most
120 fitness evaluations per run (minus cache hits), comparable to
OptunaSearch with 20 trials but with higher per-evaluation overhead on large
datasets.

\textbf{Low-dimensional tasks.}
On datasets where linear models are near-optimal (Wine, Breast Cancer), the
structural search overhead does not pay off.
The complexity penalty $\lambda|V|$ mitigates but does not fully close this
gap.
An adaptive $\lambda$ schedule that increases during later generations would
more aggressively prune redundant topology.

\textbf{Search space boundary.}
The current registry has 12 operations.
Adding LightGBM, XGBoost, or deep feature embeddings would expand the search
space but also increase the topology search cost quadratically.
Portfolio selection for the registry is an open problem.

%%% 7. CONCLUSION %%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\section{Conclusion}

We presented C60.ai, a genetic AutoML framework that searches over the space
of all type-valid DAG pipeline topologies rather than a fixed template.
By evolving graph structure alongside hyperparameters, C60.ai expresses and
discovers pipelines that no fixed-template system can represent.

Our main findings are:
(i)~C60.ai achieves the highest mean accuracy (94.95\%) among ten sklearn
baselines across seven diverse datasets, ranking first on the three
highest-complexity tasks;
(ii)~in a nine-system AutoML comparison, C60.ai achieves the best
single-system accuracy on Digits (98.83\%) and Waveform (86.70\%) — the
two tasks where pipeline topology is the decisive factor;
(iii)~the ablation study (C60.ai-Full vs.\ C60.ai-HPO, 9 paired evaluations
per dataset) reveals a task-dependent structural search advantage: +1.33\,pp
on Iris ($p{=}0.031$) with statistical parity on Wine, Breast Cancer, and
Digits, yielding a mean gain of $+0.25$\,pp — consistent with the
budget-complexity trade-off analysed in Section~\ref{sec:discussion};
and
(iv)~the structure-hash cache reduces fitness evaluations by 20--40\% at
no accuracy cost.

\paragraph{Future work.}
Three directions are most promising:
(1)~\emph{Adaptive complexity pressure} — anneal $\lambda$ to permit early
structural exploration and suppress bloat in later generations;
(2)~\emph{Crossover via common subgraph identification} — replacing
depth-matching crossover with maximum common subgraph isomorphism would
enable more semantically meaningful recombination;
(3)~\emph{Meta-learning warm-starts} — initialising the population with
topologies from a library of historically successful pipelines would reduce
the exploration budget needed on new datasets.

\section*{Broader Impact}

This work advances AutoML by removing the topology assumption that all
mainstream systems silently impose.
Democratising topology-aware ML tooling benefits practitioners in
resource-constrained settings where expert pipeline design is not feasible.
The system is fully open-source and all benchmarks are reproducible.
No specific negative societal impacts beyond those common to general
ML development are anticipated.

\section{Evolutionary Algorithm}
\label{app:alg}

\begin{algorithm}[H]
  \caption{C60.ai Evolutionary Search}
  \label{alg:c60}
  \begin{algorithmic}
    \STATE {\bfseries Input:} Dataset $(X, y)$, population size $P$,
      generations $G$, elitism $e$, penalty $\lambda$,
      \texttt{structural\_search} $\in \{$\texttt{True, False}$\}$
    \STATE {\bfseries Output:} Best pipeline $G^*$
    \STATE Initialise $\mathcal{P}_0 \leftarrow$ random typed DAGs
    \FOR{$t = 1$ {\bfseries to} $G$}
      \FOR{each $G \in \mathcal{P}_{t-1}$}
        \IF{$h(G) \in \textsc{Cache}$}
          \STATE $\mathcal{F}(G) \leftarrow \textsc{Cache}[h(G)]$
        \ELSE
          \STATE $\mathcal{F}(G) \leftarrow \overline{\mathrm{CV}}_k(G, X, y)
            - \lambda|V|$
          \STATE $\textsc{Cache}[h(G)] \leftarrow \mathcal{F}(G)$
        \ENDIF
      \ENDFOR
      \STATE $\mathcal{P}_t \leftarrow$ top-$e$ elites from
        $\mathcal{P}_{t-1}$ \COMMENT{Proposition~\ref{prop:monotone}}
      \WHILE{$|\mathcal{P}_t| < P$}
        \STATE $G_1, G_2 \leftarrow \textsc{TournamentSelect}(k_t{=}3)$
        \IF{\texttt{structural\_search}}
          \STATE $G' \leftarrow \textsc{SubgraphCrossover}(G_1, G_2)$
          \STATE $G' \leftarrow \textsc{StructuralMutate}(G')$
        \ELSE
          \STATE $G' \leftarrow G_1.\textsc{Clone}()$
        \ENDIF
        \STATE $G' \leftarrow \textsc{HyperparamMutate}(G')$
        \STATE $\mathcal{P}_t.\textsc{add}(G')$
      \ENDWHILE
    \ENDFOR
    \STATE \textbf{return} $\arg\max_{G \in \mathcal{P}_G} \mathcal{F}(G)$
  \end{algorithmic}
\end{algorithm}

\section{System Architecture}
\label{app:arch}

C60.ai is implemented in pure Python 3.10+ with
scikit-learn~\cite{pedregosa2011scikit} as the operation backend and
optional PyTorch~\cite{paszke2019pytorch} hybrid nodes.

\begin{itemize}
  \item \texttt{c60/core/} — typed DAG, operation registry, data-type lattice
  \item \texttt{c60/evaluation/} — fitness evaluator, per-fold timeout,
        evaluation cache
  \item \texttt{c60/evolution/} — population manager, genetic operators,
        GA engine (including \texttt{structural\_search} ablation flag)
  \item \texttt{c60/explainability/} — PipelineStory narrative,
        feature introspection
  \item \texttt{c60/hybrid/} — PyTorch autoencoder and MLP as pipeline nodes
  \item \texttt{c60/api/} — FastAPI async REST server
  \item \texttt{c60/cli/} — Click CLI: \texttt{c60 run / explain / info}
\end{itemize}

A test suite of 374 pytest tests achieves full module coverage.
Benchmark infrastructure (\texttt{benchmark/}) implements incremental
result writing with resume support, ablation tooling, and automated
report generation.
